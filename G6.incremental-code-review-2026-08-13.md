## Findings

### P1-1: Partial answers are excluded from the wrong-answer teaching loop

`ChoiceGradingPolicy` now returns `AttemptResult.Partial` for a correct but incomplete multi-answer selection. Submission persists the result and creates a provisional diagnosis, but downstream consumers still select only `Incorrect`:

- `web/src/modules/evidence/application/GetWrongBookEntries.ts:64-66,84-94`
- `web/src/modules/evidence/application/ObjectiveSubmissionPostProcessor.ts:150-165`
- `web/src/modules/tutoring/application/RecordObjectiveTutorConclusion.ts:49-51`
- `web/src/features/practice/TutorPracticeSessionView.vue:61-89,484-486,541-545,609`
- `web/src/services/QualityDashboardService.ts:249,278`

As a result, a partial answer is scored but does not enter the wrong book, does not receive AI diagnosis, is absent from the tutor conclusion's error set, and cannot use the diagnosis confirmation or "ask AI" actions. It also leaves a provisional diagnosis that no queued task completes.

**Required fix:** define a single domain predicate for results requiring correction (normally `Incorrect` and `Partial`) and use it in wrong-book projection, diagnosis dispatch, tutor conclusion, quality statistics, and UI state. Add an end-to-end verifier from multi-answer submission through wrong-book and diagnosis dispatch.

### P1-2: Imported multi-answer content is published as single-choice metadata

The parser and `QuestionContent` contract accept `multiple_choice` and `indeterminate_choice`, but `PublishQuestionImportDraft` resolves one single-choice schema/template and assigns those IDs to the generation spec and every question:

- `web/src/modules/content/application/PublishQuestionImportDraft.ts:106-120,130-138,181-203`
- `web/src/modules/content/fixtures/content-metadata-v2.json:29-72`
- `web/src/modules/agent/fixtures/tutorToolCatalog.ts:25-55`

The metadata fixture contains no multi-answer schema/template, and the import tool schema exposes only `correctOptionId`. A question can therefore contain `templateCode=multiple_choice` and `correctOptionIds` while its persisted version IDs assert `single_choice`.

**Required fix:** add published metadata for every supported choice template, resolve metadata per candidate, and either split heterogeneous imports into compatible generation specs or model per-question schema/template ownership explicitly. Extend the import tool contract with a discriminated answer shape and add multi/indeterminate import tests.

### P2-1: Prompt bundle conflicts create two meanings for one version

`InstallExamPacks` registers the bundled prompt in memory before `EnsurePromptBundle` checks persisted metadata, and ignores the returned `Conflict` status:

- `web/src/composition-root/curriculum/InstallExamPacks.ts:25-31`
- `web/src/capabilities/ai-runtime/prompt/EnsurePromptBundle.ts:19-35,43-51`

Business operations compile from the in-memory registry, while structured generation recovery loads the persisted prompt by ID (`RunStructuredObjectiveGenerationWorkflow.ts:130-132`). If prompt content changes without a version bump, fresh execution and durable recovery can use different text under the same version.

**Required fix:** make same-version content conflicts fail the affected prompt installation or register the persisted bundle into runtime. Never continue with two content hashes for one `(examType, promptCode, version)`. Update the verifier to assert runtime and persistence converge after a conflict.

### P2-2: Durable business tasks do not capture their exam-pack prompt scope

`PromptRegistry` resolves against mutable global `activeExamType`, and business tasks compile only when a worker executes them:

- `web/src/capabilities/ai-runtime/prompt/PromptRegistry.ts:12-38`
- `web/src/capabilities/ai-runtime/prompt/PromptCompiler.ts:7-14`
- `web/src/composition-root/agent/createTutorAgentHandlers.ts:229-252`

A queued or recovered task created for pack A can compile with pack B after the active candidate track changes. This is not observable with the single currently bundled pack, but it breaks the new multi-pack contract.

**Recommended fix:** snapshot `examType` plus prompt version/content hash in the durable task at creation, and compile by that immutable identity. Keep a global active pack only as a UI/default selection concern.

### P2-3: An unknown current exam type is silently rebound to the first pack

`resolveActivePack` falls back to `packs[0]` even when an existing cycle has an unsupported `examType`, then `AlignCandidateCurriculum` changes its curriculum and policy bindings without changing that exam type:

- `web/src/composition-root/curriculum/InstallExamPacks.ts:43-48`
- `web/src/modules/candidate/application/AlignCandidateCurriculum.ts:33-59`

This can create a cycle whose `examType` names one track while its curriculum belongs to another. First-pack fallback is valid before onboarding, not for an already identified cycle.

**Recommended fix:** use the default only when no cycle exists. For an unknown existing type, preserve the last valid binding and surface an explicit unsupported-pack state.

### P2-4: One-shot practice auto-start cannot recover from a transient failure

`usePracticeSelfAutoStart` sets `handledKey` before awaiting generation and removes `start=1` only after success:

- `web/src/features/practice/usePracticeSelfAutoStart.ts:24-43`

If generation fails, the URL still requests auto-start but the same mounted page refuses to retry because the request is already marked handled. The knowledge-map action can therefore appear permanently stuck until navigation or reload.

**Recommended fix:** mark the request consumed only after successful enqueue, or clear `handledKey` in `catch/finally`. Include `count` in the watched request identity and expose an explicit retry state.

### P2-5: Choice scoring policy bypasses the new exam-pack policy boundary

Partial-credit behavior is encoded as global constants in `ChoiceGradingPolicy.ts:12-25,30-51`, and the same rule is repeated as UI copy in `QuestionContentTemplate.vue:91-93`. The new curriculum-pack design says scoring policies belong to the exam package, but future packs cannot replace this rule.

**Recommended fix:** resolve a versioned objective grading policy from the session/generation metadata. Render explanatory copy from the same policy projection so scoring and UI cannot drift.

### P2-6: Restored onboarding drafts are not revalidated against installed packs

`OnboardingView` loads pack defaults first and then blindly restores every same-primitive-type field from the draft:

- `web/src/features/onboarding/OnboardingView.vue:258-270,292-303`

An old draft can restore a removed `examType` and stale score maps after defaults were applied. Later form validation may block submission, but the user sees a broken selection state instead of a deliberate migration/recovery path.

**Recommended fix:** validate the restored exam type against `examPacks`, then normalize score maps against that pack's scored subjects and apply defaults for missing entries.

### P3-1: Selected-answer labels preserve tap order rather than option order

`submittedAnswerLabel` joins persisted IDs without sorting (`ChoiceAttemptAnswer.ts:13-21`). Selecting C and then A can display `CA` while the correct label is rendered as `AC`, although grading is set-based.

**Recommended fix:** normalize selected IDs to the question option order before persistence/display, or pass option order into the presenter.
