# Zhangl Agent 架构宪法

> 状态：生效  
> 适用范围：Vue/Capacitor 客户端、本地数据层、AI 工作流、提示词、iOS 原生插件及后续新增业务。  
> 产品定位：以尽可能少但足够精准的教学和训练，持续解决个人真实能力缺口，并对目标分提升负责的本地优先 AI 公考私教。

## 1. 宪法效力

决策冲突时按以下优先级处理：

```text
本架构宪法
→ 产品能力闭环重构计划
→ Architecture Decision Record（ADR）
→ 领域合同、Schema 和 API 合同
→ 具体实现与页面需求
```

- 页面效果、开发速度和历史代码不能成为违反宪法的理由。
- 任何例外必须写 ADR，说明原因、影响、退出条件和最晚清理时间。
- 宪法修改必须说明产品定位是否变化，并同步更新验收标准；不能通过局部代码静默改变架构方向。
- 当前产品未上线，不保留旧业务模型、旧数据或旧接口兼容层。

## 2. 产品法则

### 第一条：能力结果优先于使用量

刷题数、在线时长和 AI 调用次数只是过程数据。产品首先优化：

- 知识缺口消除率。
- 掌握保持率和迁移成功率。
- 达到稳定掌握所需时间与题量。
- 预测分与真实模考/考试结果的校准误差。
- 计划对个人现实时间约束的适配度。

禁止用“多生题、多提醒、多聊天”代替教学效果。

### 第二条：每个教学动作必须服务于能力闭环

计划、讲义、题目、错题、批改、复习、对话和通知必须至少关联：

```text
exam_cycle_id
capability_node_id
learning_thread_id（教学动作存在时）
教学目的或评估目的
```

无法说明“为哪个目标、解决什么能力缺口、如何验证效果”的功能，不进入核心业务。

### 第三条：长期教学主线不能被页面和日期割裂

系统以 `learning_thread` 承载一个能力缺口从发现到稳定掌握的跨日过程。每日计划只是主线在某一天的切片，聊天会话和页面也不能成为教学事实边界。

### 第四条：训练不等于掌握

讲过、提示过、同模板重复过的题只能证明训练完成。进入稳定掌握必须依赖无提示、未泄题、跨时间且足够新颖的保持、迁移或锚定评估证据。

### 第五条：同错不同教

教学路径由错误阶段、错因、前置缺口、速度、保持和迁移表现共同决定。禁止仅依据“答错”重复生成同类题。

### 第六条：AI 私教应主动，但用户拥有最终控制权

- 代码从事实中检测值得干预的信号，AI 负责形成自然且具体的教学建议。
- 主动建议必须可解释、可忽略、可降频。
- 改目标、重排阶段、批量生成和删除数据等高影响动作必须确认。
- 主动不等于高频打扰，不以制造焦虑提高使用时长。

## 3. 领域法则

> 编码层面的模块、分层、公开合同、Registry 和 Composition Root 必须遵守 [模块化分层与组合编码标准](./modular-architecture-standard.md)。

### 第七条：按业务事实划分边界

考试周期、课程能力、学习证据、学生模型、教学、计划、内容、AI 私教和任务执行各自拥有清晰职责。跨领域通过 Application Use Case 和领域事件协作，页面、Store 和 AI Runner 不得拼装跨领域写入。

### 第八条：一个业务不变量只有一个所有者

例如：

- 掌握状态只能由 `MasteryPolicy` 推进。
- 每日计划版本只能由 Planning Context 创建。
- 证据有效性只能由 Evidence Correction 流程改变。
- AI 任务状态只能由 Task State Machine 改变。

不得在多个 Service、页面或提示词里各写一套同名规则。

### 第八条补充：组合必须受合同约束

系统采用模块化单体。业务模块、功能能力和页面 Feature 分开；模块内部实现不可跨边界导入。所谓自由组装，仅允许通过公开 Command、Query、Event、Port、Registry 和 UI Slot 完成，禁止形成任意依赖网。

### 第九条：能力图谱高于题目分类

图谱统一表达知识、认知能力、解题技能、考试策略和表达能力。题目类型只是内容属性，不能代替能力模型。

### 第十条：客观题与主观题共享框架，不共享评分算法

行测、申论和面试共享证据链、计划、任务和教学主线；评分、掌握、分数预测和质量校验由各自版本化 Policy 实现。

## 4. 数据法则

### 第十一条：SQLite 是业务事实真相源，Agent 工作区不混入业务库

- 核心业务使用关系字段、外键、唯一约束和索引。
- JSON 只保存内容块、模型原始结构和低频扩展配置。
- 考生档案、目标、计划、题目、作答、评分、错因、证据、掌握度和学习资产属于业务事实。
- 对话正文、会话摘要、Agent 记忆和临时工具明细属于 Agent 工作区；使用可删除的文件日志或有界内存，不进入 SQLite/IndexedDB 业务表。
- 可恢复的 AgentRun、Outbox、幂等回执和模型调用审计是业务工作流运行状态，可以结构化持久化，但不得包含隐藏思考或完整对话副本。
- `learning_evidence` 是可纠正的追加事实。
- 错因诊断、确认和纠正也是追加事实；原始诊断不得被页面或 AI 覆盖，当前状态仅能由可重算投影提供。
- 掌握画像、预测分和页面统计是带算法版本的可重算投影。
- IndexedDB 只实现同一 Repository 合同，不能形成另一套业务语义。

### 第十二条：任何半份业务结果都不允许存在

跨表业务写入必须具备：

- Unit of Work 事务。
- 命令和结果幂等键。
- 外键与唯一约束。
- 乐观并发版本检查。
- 事务内 Outbox。
- 可恢复检查点。

UI 显示“已完成”前，业务结果必须已经可靠落库。

事务边界遵守以下分类：

- 核心原子事务：业务事实、幂等回执、聚合版本和对应 Outbox 必须一起提交。
- 独立写入：不参与同一业务不变量的审计状态、可重算投影和展示状态，不得被强行并入核心事务。
- 事务后任务：模型调用、通知投递、能力重算、计划重排和消息投影通过 Outbox 或 AgentRun 在提交后执行。
- 维护事务：数据库迁移、完整备份恢复和清理使用明确的 `maintenance` workload，不得借此扩大日常交互事务。

普通核心事务总时长必须有界，超过预算立即停止接收后续 SQL 并回滚。Repository 在持有 `TransactionContext` 时只能通过该上下文读写，禁止再次调用全局数据库连接形成锁重入。事务外先完成模型请求、文件处理、长计算和不要求快照一致性的读取，只把最终必要事实带入事务。

SQLite 的 `runAutocommit` 只省略显式 `BEGIN/COMMIT`，单条 SQL 仍由 SQLite 提供隐式原子性。它仅允许承载一项独立 Repository 写入；不得用于多个核心事实、读后写不变量或 Outbox 配对提交。

### 第十三条：错误数据必须可撤销、可追溯、可重算

AI 错题、错误答案、误判错因和用户纠正不能物理篡改历史。通过纠错记录使原证据失效或被替代，再重算受影响投影和计划。

### 第十四条：本地优先不等于没有数据保护

- API Key 存 Keychain。
- 学习数据库使用 Keychain 管理的密钥加密。
- 提供加密备份、恢复、完整导出和彻底删除。
- 启动时执行轻量完整性检查，异常时禁止继续写入并进入恢复流程。
- SQLite 访问必须经过单写队列和数据库生命周期门禁；锁等待、Bridge 调用和恢复动作均有明确超时。
- App 从后台恢复时必须废弃旧锁队列、使旧连接代次失效、回滚遗留事务、关闭并重建连接，然后恢复连接级 PRAGMA 并执行 `quick_check`。
- 连接恢复完成前，页面查询、Agent、生题、批改、Outbox 和后台维护不得继续访问数据库；旧代次事务不得在恢复后提交。
- 网络、模型推理、长轮询和文件处理禁止置于数据库事务内。高基数事实使用批量 SQL，事务只保护必要业务事实与 Outbox。
- 运行时超时恢复失败时允许重建 Web Runtime，但不得清库、要求重装或丢弃用户业务数据。
- 模型请求只发送完成当前任务所需的最少数据。

### 第十五条：版本是业务数据的一部分

课程版本、题目内容版本、评分 rubric、提示词、工具 schema、模型、掌握算法和计划算法都必须可追溯。版本升级不得静默改变既有证据语义。

确定性状态、标识、标题映射、文件命名和规则参数必须有单一所有者。禁止在页面、Service、Prompt 和数据库中重复散落魔法字符串、中文三元表达式和无单位魔法数字。

## 5. AI 法则

### 第十六条：AI 提案，代码裁决

AI 可以提出计划、错因、教学动作、内容和评分建议，但不能直接修改掌握度、预测分、计划完成状态和复习状态。结构校验、领域校验和事务提交必须由代码完成。

### 第十七条：结构化合同是 AI 与业务的边界

- 工具只暴露标准 description 和参数 schema。
- 具体提示词按任务动态加载。
- AI 输出先通过 Schema Validator，再通过 Domain Validator。
- 不确定意图和低置信度诊断必须向用户确认。
- 结构修复有上限；失败后明确降级，不伪造成功。

结构化合同只约束系统必须掌握的事实和页面必须渲染的关系，不能演变成固定内容模板：

- **结构硬边界**：字段类型、稳定标识、题目与选项关系、答案引用、共享材料引用、内容块类型、评分量表维度和可落库性由代码裁决。
- **安全范围边界**：最大题量、最大章节数、最大列表项、输出 token、超时和并发只用于保护设备、成本与稳定性。
- **教学必达目标**：提示词应说明必须讲清的核心概念、方法适用条件、关键易错点、考试关联和可执行学习动作，但不能用固定字数和固定条数替代质量。
- **AI 自主区域**：章节数量与顺序、讲解深度、案例和方法数量、表达形式、内容取舍及教学节奏由 AI 根据学生证据、任务目的和内容复杂度决定。
- 用户明确选择的题量、模块和难度属于命令合同；私教模式中的这些参数应由计划/教学 Agent 在生成前决策。内容生成 Agent 负责执行，不得在输出阶段暗自改变目标。

新增生成规则时必须说明其属于上述哪类。无法证明会影响渲染、数据正确性、安全或明确教学必达目标的规则，默认不得作为阻断校验。

### 第十八条：上下文只保留教学必要信息

上下文由当前考试周期、活动学习主线、相关证据、计划约束和必要对话摘要动态构建。禁止注入全量聊天、全量学习历史和模型思考过程。

### 第十九条：模型调用必须可归因、可降级

每次调用记录任务、供应商、模型、提示词版本、工具版本、token、耗时、重试和结果质量。限流或失败时按策略降低并发、切换模型角色或退回本地基础方案，不能让核心页面失去可用性。

### 第二十条：延迟和成本属于教学体验

本地可可靠完成的统计、排序、状态迁移和基础计划不得调用 AI。内容生成分批落库并尽快展示首批结果；缓存只能复用稳定教学资产，不能缓存用户状态判断。

## 6. 体验法则

### 第二十一条：用户永远看得到真实状态和下一步

耗时操作必须立即出现任务状态，支持取消、恢复和失败说明。页面重进后从数据库恢复真实状态；任务完成后刷新目标资源，不能依赖内存事件或用户重新进入页面。

### 第二十二条：界面围绕当前教学任务组织

首页是计划中心，刷题页是执行空间，能力页解释变化，AI 对话框承接私教互动。页面不因展示统计、装饰或重复控件挤占题干、作答和反馈空间。

### 第二十三条：同一语义使用同一组件和交互

头部层级、弹窗分类、空状态、任务状态、Markdown 内容块、题目区域、作答区域、解析区域和错因区域必须由公共组件与设计令牌约束。特殊模板只能扩展固定内容块，不能重写全套语义。

### 第二十四条：可访问性和真机行为是完成条件

字体缩放、安全区、键盘、前后台切换、离线、杀进程恢复、VoiceOver、对比度和触控面积必须纳入验收。网页能运行不等于 iOS 功能完成。

## 7. 演进法则

### 第二十五条：先建立垂直闭环，再扩展功能数量

优先完成一个能力缺口从诊断、讲解、训练、批改、复习到迁移验证的完整纵向切片，再复制到更多模块。禁止同时铺开大量只有入口、没有证据回流的功能。

### 第二十六条：抽象由业务不变量驱动

只有当多个模块共享相同业务语义和生命周期时才建立公共抽象。仅 UI 相似不代表同一领域对象；仅代码重复也不必提前建立复杂框架。

### 第二十七条：新数据库只面向自身演进

当前 clean break 不实现旧数据迁移。新 schema 上线后必须使用前向 migration、备份和回滚预案保护新数据，不能再以“还在开发”为由任意破坏已产生的新学习事实。

## 8. 强制质量门槛

任何核心功能合并前必须回答并验证：

1. 它服务哪个考试目标和能力缺口？
2. 它属于哪个领域，谁拥有写入不变量？
3. 输入事实、输出事实和可重算投影分别是什么？
4. 失败、重试、取消、并发和杀进程后状态如何恢复？
5. AI 不可用时最低可用路径是什么？
6. 错误 AI 结果如何纠正并消除对画像的污染？
7. 是否发送个人数据，是否满足最小化原则？
8. 常用查询是否命中索引并符合性能预算？
9. 用户是否知道为什么这样安排，并拥有拒绝权？
10. 是否用保持或迁移证据验证了真实学习效果？

自动化架构检查至少包括：

```text
页面/Store/Domain/AI Runner 禁止直接导入数据库适配器
页面禁止直接更新 mastery、evidence、plan 和 task 核心表
所有 AI 输出必须经过版本化 schema
所有跨表命令必须通过 Unit of Work
所有核心写命令必须携带 idempotency_key
所有投影记录 algorithm_version
所有活动任务必须关联 workflow_id 和目标资源
所有训练内容必须标记 assessment_role
```

## 9. ADR 约定

以下变更必须写 ADR：

- 新增或拆分领域边界。
- 修改事实源或聚合所有权。
- 修改掌握、复习、计划或评分算法。
- 引入新的数据库、云服务或模型供应商能力。
- 修改隐私边界、加密或备份方案。
- 违反本宪法的临时例外。

ADR 最少包含：背景、决策、备选方案、产品定位影响、数据影响、性能影响、风险、验证方式和退出条件。

## 10. 北极星验收

架构最终必须支持并证明：

> 系统能说明这个考生距离目标还差什么、为什么会错、当前正在解决哪条能力主线、采用过哪些教学方法、哪种方法有效、何时需要复习，以及通过什么独立证据确认已经真正掌握。

任何不能让这段话更真实的复杂度，都应被质疑。
